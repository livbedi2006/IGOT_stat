How to use this document
Complete the tasks in the stated order. Copy each prompt into your preferred coding assistant only after the
prerequisite feature is working. Replace mock catalogue data with authorized iGOT/NSSTA data only when access
and approval are available. The Docker files included here make the prototype easier to run consistently across
laptops, but Docker still requires Docker Desktop or Docker Engine on the host device.

3. Catalogue and recommendation prompts
Prompt F — iGOT-ready integration adapter
 Design a CourseProvider adapter for STATWISE. Support MockIGOTProvider now and IGOTApiProvider later using
IGOT_API_BASE_URL, IGOT_CLIENT_ID and IGOT_CLIENT_SECRET environment variables. Do not hardcode endpoints or claim live
access without credentials.
Normalize: provider, external_course_id, title, description, competencies_taught, difficulty, duration_hours, language, mode, url, rating,
availability_status and last_synced_at. Add timeout, retries, cache, audit logs and fallback to last successful catalogue sync.
Prompt G — NSSTA/TPAC programme module
 Create an NSSTA/TPAC programme catalogue. Fields: programme_id, title, source, description, competencies, target role, level,
online/classroom/blended mode, duration, location, schedule, nomination method, prerequisites, official source reference and verification
date.
Provide at least 15 clearly labelled demo records. Add admin CRUD/verification controls and filters for competency, role, mode, duration
and date. Design it so seed records can later be replaced by approved data.
Prompt H — Explainable recommender
 Implement an explainable hybrid recommender. Retrieve options for priority gaps from iGOT-ready and NSSTA/TPAC catalogues;
exclude completed courses and unmet prerequisites. Score using gap coverage 35%, role relevance 25%, difficulty fit 15%, prerequisite
readiness 10%, department priority 10%, duration/language 5%.
Return title, provider, competency, score, estimated duration, mode, prerequisites, why_recommended, next_step and enrolment
URL/mock action. Sequence results Foundation → Core → Practice → Advanced. Provide fallback when no result qualifies.
Prompt I — Semantic search enhancement
 Add semantic search without replacing transparent rules. Generate embeddings from course title, description, objectives and tags. Store
in FAISS, pgvector or a vector database. Use semantic retrieval only to find candidates, then combine it with the existing rule score. Add
filters for provider, language, level, duration and mode. Persist recommendation reason and component scores. Provide fallback if vector
search is unavailable.

4. Assessment and tutor prompts
Prompt J — Secure document upload
 Implement secure upload for PDF, PPTX, DOCX, TXT and transcript text. Validate extension and MIME type on the server; impose
file-size limit; sanitize names; generate unique storage IDs; reject malformed files; save uploader, hash, source type, access level and
processing status. Only uploader, authorized trainers and admins may access source files. Provide clear client progress/errors and
object-storage/local-volume support.
Prompt K — Grounded MCQ pipeline
 Build a document-grounded MCQ pipeline: extract text; preserve page/slide references; remove boilerplate; section-aware chunking;
retrieve useful chunks; generate strict JSON; validate; save as drafts.
MCQ must include question, exactly four options, correct option index, explanation, difficulty, Bloom level, competency IDs, source file ID,
source page/slide, supporting source text, confidence and review status. Require evidence for correct answer; avoid
all/none-of-the-above; never auto-publish.
Prompt L — MCQ quality validator
 Create an MCQ quality validator. Reject/flag: fewer/more than four options; invalid correct index; duplicate options; answer leaked in
question; missing evidence/page; inconsistent explanation; duplicate/near-duplicate question; ambiguous wording; absent competency
tag.
Return pass/fail, executed checks, warnings, confidence, rejection reason and regeneration instruction. Include tests for valid and invalid
examples.
Prompt M — Trainer review and publishing
 Build a trainer review workflow. Display original source page/slide beside each question. Allow edit, approve, reject, regenerate, duplicate
and delete. Assemble approved questions into quiz with title, duration, attempts, passing score, dates and assigned cohort. Include
preview, JSON/CSV export and an audit trail. Use statuses: Draft → Under Review → Approved → Published → Archived.
Prompt N — Learner quiz and competency update
 Build learner quiz flow: one question at a time, progress, optional timer, autosave, randomized option order, auto-submit on expiry and
result page. Result shows score, answers, explanations, competency-wise performance and revision recommendations. Update
competency evidence only from approved quizzes. Keep answers hidden until submission and support keyboard/mobile access.
Prompt O — Source-grounded tutor
 Implement a RAG AI tutor using only approved NSSTA material, trainer-approved uploads, curated course metadata and official
glossaries. Retrieve source chunks before response. Every answer shows source title and page/slide. If evidence is absent, say it cannot
be verified from approved material and direct the learner to a trainer/official reference. Enforce access permissions and collect
helpful/not-helpful feedback.

6. Docker: run on any development device
Docker is the right addition. It packages your backend, frontend, PostgreSQL database, Redis queue and background
worker with matching dependencies. Teammates can use the same command rather than manually configuring Python,
Node.js, PostgreSQL and Redis. It does not remove the need to install Docker Desktop (Windows/macOS) or Docker
Engine + Compose plugin (Linux).
Recommended command
From the repository root, run: docker compose up --build. Then open the frontend at http://localhost:3000 and
FastAPI documentation at http://localhost:8000/docs. For a clean reset of local demo data, run: docker compose
down -v and then start again.

Backend Dockerfile — backend/Dockerfile
 FROM python:3.11-slim
WORKDIR /app
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential libpq-dev && rm -rf /var/lib/apt/lists/*
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
Frontend Dockerfile — frontend/Dockerfile
 FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
ARG NEXT_PUBLIC_API_URL=http://localhost:8000
ENV NEXT_PUBLIC_API_URL=$NEXT_PUBLIC_API_URL
RUN npm run build
FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/public ./public
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./package.json
EXPOSE 3000
CMD ["npm", "start"]

    image: redis:7-alpine
    command: redis-server --appendonly yes
    volumes:
      - redis_data:/data

      test: ["CMD", "redis-cli", "ping"]

      timeout: 3s
      retries: 12
  backend:
    build: ./backend
    env_file: .env
    environment:
      DATABASE_URL: postgresql+psycopg2://${POSTGRES_USER:-statwise_user}:${POSTGRES_PASSWORD:-change_me}@postgres:5432/${POSTGRES_DB:-statwise}

      - uploads_data:/app/uploads
    ports:
      - "8000:8000"

      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy

Important Docker notes
1. Do not commit .env, credentials, local databases, model weights or uploaded official materials. Commit only
.env.example. 2. The worker command assumes Celery is configured at app/celery_app.py; adjust the module name if yours
differs. 3. For local demonstration, frontend uses localhost:8000. In cloud deployment, rebuild it with the public backend
HTTPS URL. 4. Run database migrations/seed data from an entrypoint or a separate command after containers are healthy.
5. Before showing the final demo, test the full stack on a teammate’s laptop using only the repository and Docker Compose.
